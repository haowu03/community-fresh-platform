# 使用教程与启动指南

## 一、必须启动的服务（4 个，缺一不可）

| 服务 | 作用 | 不启动的后果 |
|---|---|---|
| MySQL 8 | 业务数据库 | 后端启动失败 |
| Redis | 缓存 / 下单防重锁 | 商品浏览、下单等接口报"系统繁忙" |
| 后端 fresh-server | RESTful 接口（8080） | 前端全部无法访问 |
| 前端 fresh-admin / fresh-user | 管理端 5173 / 用户端 5174 | 没有页面 |

> 前端两个工程相互独立，可以只启动其中一个。

## 二、启动步骤（按顺序）

### 1. MySQL
Windows 已安装为服务的一般已自启。检查：任务管理器 → 服务 → MySQL80 正在运行。

首次使用需初始化数据库（只执行一次）：
```bash
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 < sql\community_fresh.sql
```
演示数据（可选，已导入过可跳过）：
```bash
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 community_fresh < sql\demo-data.sql
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 community_fresh < sql\demo-data2.sql
```

### 2. Redis（每次开机都要手动启动）
本机 Redis 解压目录：`C:\Users\16098\Desktop\redis\`
```bash
Start-Process "C:\Users\16098\Desktop\redis\redis-server.exe"
```
> 弹出的黑色窗口**不要关闭**，关闭即停止 Redis。
> 验证：`& "C:\Users\16098\Desktop\redis\redis-cli.exe" ping` 返回 `PONG` 即正常。

### 3. 后端
IDEA → 打开 `fresh-server` 目录 → 等待 Maven 依赖下载 → 运行 `com.fresh.FreshApplication`。
启动成功日志：`社区便民生鲜配送平台启动成功`，端口 8080。
接口文档（Knife4j）：http://localhost:8080/doc.html

> 数据库账号密码在 `fresh-server/src/main/resources/application.yml`（当前 root / 123456），与本机不一致时改这里。

### 4. 前端（两套）
双击根目录的 `start_fresh_front.bat`，会同时拉起两套前端：
- 管理端：http://localhost:5173
- 用户端：http://localhost:5174

手动启动方式：
```bash
cd fresh-admin && npm.cmd run dev    # 管理端 5173
cd fresh-user  && npm.cmd run dev    # 用户端 5174
```

## 四、功能使用教程

### 4.1 管理端（admin 登录 5173）
- **数据看板**：营业额、订单量、销量 Top 统计图表
- **商品管理**：新增/编辑商品（保鲜类型、保质期、是否按重计价）→ **批次入库**（填生产日期，自动算到期日）→ 库存预警列表
- **分类管理**：分类增删改、启停
- **订单管理**：待接单 → 接单 → 备货完成（自提单此时生成自提码）→ 派送/完成；也可输入自提码核销
- **预售管理**：发布预售活动（预售价、截止时间、发货日期）
- **团购管理**：查看平台所有团购活动进度
- **社区管理**：帖子审核（用户发帖需审核后可见）
- **员工管理**：管理端账号维护

### 4.2 用户端（user1 登录 5174）
- **首页**：搜索、临期特价 / 预售 / 团购三个快捷入口、分类筛选、商品浏览
- **分类**：左侧分类栏切换，右侧联动该分类商品
- **商品详情**：价格、产地、保质期、批次、溯源信息（产地/种植户/检测报告）
- **加购**：
  - 按份商品（鲜鸡蛋、大米、**整条鱼/整盒海鲜**）→ 选份数
  - 按重商品（蔬菜、水果、鲜肉、基围虾）→ 步进器或快捷重量选 0.5~3 斤，实时显示预估金额
- **购物车 → 提交订单**：选「配送到家」（选地址）或「社区自提」（选自提点 + 时间段）→ 模拟支付
- **自提码**：自提订单在订单详情可见 6 位自提码，到自提点出示给团长核销
- **临期特价**：每日 00:30 定时任务把临期批次自动打 7 折，在此专区展示
- **预售专区**：立即预订 → 称重商品先选重量 → 下单支付
- **社区团购**：参团下单 → 满员自动成团 / 到期未满自动流团退款
- **社区**：发帖（需管理员审核）、评论、点赞
- **我的**：点头像更换头像、点名字改昵称（默认账户名）、消息通知（进入自动已读）、我的订单/地址/帖子/参团

### 4.3 团长功能（leader1 登录 5174 → 我的 → 团长专区）
- **发起团购**：选商品、定团购价、成团人数、截止时间
- **我发起的团购**：查看参团成员与进度
- **自提核销**：输入用户出示的 6 位自提码完成核销

### 4.4 完整体验路径（推荐演示顺序）
1. user1 加购（含一个称重商品）→ 下单配送到家 → 支付 → admin 接单/派送 → 订单完成 → user1 评价
2. user1 下单选社区自提 → admin 接单/备货 → 订单详情出示自提码 → leader1 核销 → 完成
3. leader1 发起团购 → user1 参团 → 满员成团（或 admin 等定时任务结算）
4. admin 发布预售 → user1 预订 → 查看订单
5. user1 发帖 → admin 审核通过 → 社区可见 → 评论点赞
6. 首页进临期特价 → 7 折商品下单

## 五、常见问题

| 问题 | 原因与解决 |
|---|---|
| 接口报"系统繁忙" | Redis 没启动或窗口被关了，重新启动 redis-server |
| 商品/临期数据不更新 | 清 Redis 缓存：`redis-cli KEYS "fresh:*"` 逐个 `DEL` |
| 页面端口不是 5173/5174 | 端口被占用时 Vite 自动顺延，以终端提示为准 |
| bat 脚本乱码 | 已改为纯英文版 `start_fresh_front.bat`，勿自行加入中文 |
| npm 命令无法运行 | PowerShell 禁脚本，用 `npm.cmd` 代替 `npm` |
| 登录提示密码错误 | 三个演示账号密码均为 123456，后端启动时 DataInitializer 会自动校正 |
